TRANSPARENCY & DATA PROTECTION

Privacy policy.

Personal Wellbeing is an independent personal-use wellbeing project in development. This policy explains the current testing purpose and data handling of its public information website.

Last updated: 19 October 2026

1. Purpose and current status

The proposed app is intended to help its owner understand associations between habits and wellbeing. No functioning public habit-tracking product is deployed here. This website provides project information and its privacy policy only.

2. Google data and permissions

During testing, the owner may explicitly authorize read-only access to Google Health activity and fitness, sleep, and health metrics or measurements. These categories include workouts, steps, sleep sessions and stages, heart rate and weight. This project does not request permission to edit or delete Google Health data.

3. How data is used

The owner authorizes read-only access to selected Google Health records for private personal-development testing. A Cloudflare Worker currently imports daily wearable step totals. If the owner installs the optional sleep upgrade, that Worker will additionally fetch reconciled Google/Fitbit wearable sleep sessions for the latest seven local wake-up dates (Europe/Brussels), selecting one primary sleep session per night and saving sleep start and end times, minutes asleep, minutes in bed, awake minutes, and light/deep/REM summary minutes where available. It does not retain the raw sleep stage timeline. It does not create a zero value for missing sleep stages.

Repeated imports update source measurements while leaving any separately stored manual duration override intact. The Google API connectivity probe checks for accessible step records without storing the measured value. This public GitHub Pages information website does not collect or store health records. Workouts, heart rate, weight, YAZIO nutrition, AI analysis and a user-facing dashboard are not operational in this module.

4. Storage, sharing, and security

This information website has no sign-in, behavioral analytics, advertisements or health-data upload forms. GitHub Pages hosts the static site and may process normal server access logs.

A separate private Cloudflare Worker stores synchronization timestamps and outcomes, daily wearable steps, and, if the sleep module is enabled, nightly sleep summaries in an EU-jurisdiction Cloudflare D1 database. The sleep record includes its Brussels wake date, UTC bedtime and wake-up times, minutes asleep and in bed, awake minutes, optional light/deep/REM minutes, source type and timestamps. Records are not made accessible through the public health-check or synchronization-status endpoints. OAuth client credentials and refresh tokens are stored as Cloudflare Worker secrets rather than in source files or D1. Cloudflare encrypts D1 data at rest and connections use TLS. EU database jurisdiction does not guarantee that all Worker or Google API processing remains in the EU.

Health measurements are not sold, used for advertising or sent to an external AI processor by this module. Google and Cloudflare are infrastructure/API providers for this processing.

5. User choice, retention and deletion

Only the owner authorizes Google Health read-only scopes and can revoke access through Google Account connections. Revocation stops new imports once authorization is invalid, but does not automatically erase stored D1 data. Daily steps, and nightly sleep summaries if enabled, have no automatic expiry: they remain in the owner's private D1 database until manually deleted or the database is removed. The owner can delete individual records or clear an entire table using the private Cloudflare D1 Console, disable scheduled synchronization, or remove Worker secrets. Cloudflare-managed backups may follow separate retention policies.

6. Other services

An integration with YAZIO for daily calorie intake is being investigated. YAZIO credentials and nutrition data are not collected by this website, and a YAZIO integration is not currently operational.

7. Changes

This policy describes the working step synchronization and the optional main-sleep-night upgrade. It will be revised before additional health categories, YAZIO nutrition, routine AI analysis, or another data recipient or processor is enabled.

8. Contact

For questions about the personal development project, contact the owner via the project owner's GitHub profile or the support email shown on the project's Google OAuth consent screen.

TRANSPARENCY & DATA PROTECTION

Privacy policy.

Personal Wellbeing is an independent personal-use wellbeing project in development. This policy explains the current testing purpose and data handling of its public information website.

Last updated: 19 October 2026

1. Purpose and current status

The proposed app is intended to help its owner understand associations between habits and wellbeing. No functioning public habit-tracking product is deployed here. This website provides project information and its privacy policy only.

2. Google data and permissions

During testing, the owner may explicitly authorize read-only access to Google Health activity and fitness, sleep, and health metrics or measurements. These categories include workouts, steps, sleep sessions and stages, heart rate and weight. This project does not request permission to edit or delete Google Health data.

3. How data is used

The owner authorizes read-only access to selected Google Health records for private personal-development testing. A private Cloudflare Worker imports reconciled Fitbit/Google wearable step totals for the latest seven local days and, once enabled, primary overnight sleep summaries for the latest seven wake-up days. Sleep summaries include duration, timing and light/deep/REM stages when available; raw sleep-stage timelines are not stored.

With the optional HRV module, the Worker also imports up to seven days of daily wearable heart-rate variability (HRV), including RMSSD readings measured in milliseconds. It does not import ordinary heart rate. If the owner deploys the optional weight and exercise module, the Worker additionally imports individual weight observations within the previous 90 local days and exercise sessions beginning within the previous seven local days. Weight may include manually entered Google/Fitbit records; each recorded measurement preserves its timestamp, date and kilograms. Exercise sessions store category, start/end times, duration and optional active duration, calories and distance, without GPS routes, free-form notes or raw heart-rate values.

These modules use Europe/Brussels for reporting days. Historical measurements are updated in place on subsequent imports, with separately saved manual weight corrections preserved. Missing measurements are not replaced with zeroes or estimates. The owner activates automated weight and exercise imports only after testing their data. The Google API connectivity probe checks for accessible step records without storing that step value. This public GitHub Pages information website collects no health records. YAZIO nutrition, AI processing and a user-facing dashboard are not operational in this module.

4. Storage, sharing, and security

This public information website has no sign-in, behavioral analytics, advertisements or health-data upload forms. GitHub Pages hosts the static site and may process normal server access logs.

A separate private Cloudflare Worker stores synchronization timestamps and outcomes, daily steps, sleep summaries and HRV where enabled, and weight readings and exercise summaries if the optional module is deployed, in an EU-jurisdiction Cloudflare D1 database. Stored weight records contain time, civil date, kilograms and a separate manual-override field. Exercise records contain a hashed session identifier, date, session times, activity type, durations and optional calories/distance. Neither the public health-check nor synchronization-status endpoint returns these private readings. OAuth credentials and refresh tokens are stored as Cloudflare Worker secrets, not in source files, D1 or this website. D1 data is encrypted at rest and connections use TLS. EU database jurisdiction does not guarantee all Worker or Google API processing remains in the EU.

Health measurements are not sold, used for advertising or sent to an external AI processor by this module. Google and Cloudflare are infrastructure/API providers for this processing.

5. User choice, retention and deletion

Only the owner authorizes Google Health read-only scopes and can revoke access through Google Account connections. Revocation stops new imports once authorization is invalid, but does not automatically erase stored D1 data. Imported steps, sleep, HRV, weight and exercise records have no automatic expiry and remain until the owner manually deletes them or removes the database. The owner may delete individual records or clear tables using the private Cloudflare D1 Console, disable scheduled synchronization, or remove Worker secrets. Cloudflare-managed backups may follow separate retention policies.

6. Other services

An integration with YAZIO for daily calorie intake is being investigated. YAZIO credentials and nutrition data are not collected by this website, and a YAZIO integration is not currently operational.

7. Changes

This policy describes the current personal data-import modules and optional weight and exercise upgrade. It will be revised before YAZIO nutrition, routine AI analysis, further health categories, or another data recipient or processor is enabled.

8. Contact

For questions about the personal development project, contact the owner via the project owner's GitHub profile or the support email shown on the project's Google OAuth consent screen.

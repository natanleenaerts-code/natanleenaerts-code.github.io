TRANSPARENCY & DATA PROTECTION

Privacy policy.

Personal Wellbeing is an independent personal-use wellbeing project in development. This policy explains the current testing purpose and data handling of its public information website.

Last updated: 19 October 2026

1. Purpose and current status

The proposed app is intended to help its owner understand associations between habits and wellbeing. No functioning public habit-tracking product is deployed here. This website provides project information and its privacy policy only.

2. Google data and permissions

During testing, the owner may explicitly authorize read-only access to Google Health activity and fitness, sleep, and health metrics or measurements. These categories include workouts, steps, sleep sessions and stages, heart rate and weight. This project does not request permission to edit or delete Google Health data.

3. How data is used

The owner authorizes read-only access to selected Google Health data for private personal-development testing. A private Cloudflare Worker imports Fitbit/Google Health step totals and, when enabled, overnight sleep, daily heart rate variability (HRV), individual weight measurements and exercise summaries. Historic records are updated without overriding separately saved manual corrections.

If the owner explicitly installs and connects the optional YAZIO integration, the private Worker also retrieves up to seven recent days of calorie and nutrition totals (calories, carbohydrate, protein, fat, and optionally calorie goal) via an unofficial, unsupported private YAZIO API. Individual food diary entries, meal descriptions and the YAZIO password are not retained by this module. Missing diary dates are not replaced with zeros, and manual calorie corrections remain separate from provider-imported totals. Automated YAZIO imports are disabled until the owner explicitly opts in after verifying their results.

This public GitHub Pages informational website does not collect health or nutrition data. AI analysis and a user-facing personal dashboard are not yet operational.

4. Storage, sharing, and security

This public information website has no sign-in, behavioral analytics, advertisements or health-data upload forms. GitHub Pages hosts the static site and may process normal server access logs.

A separate private Cloudflare Worker stores synchronization timestamps and outcomes, and the configured Google Health records, in a Cloudflare D1 database configured with EU jurisdiction. If the optional YAZIO integration is activated, daily nutrition totals are also stored in D1. On one-time connection, the owner's PC sends their YAZIO email and password directly to YAZIO's server (not to Cloudflare), and sends only the issued refresh token over HTTPS to the owner's authenticated Worker. The Worker encrypts the renewable YAZIO token using AES-256-GCM before storing it in D1; the encryption key is a separate Cloudflare Worker secret. This token may authorize broader account access than read-only operations, though this project only reads nutrition totals. The token can be decrypted by the Worker to renew access, and is never returned by the public status endpoints.

Google OAuth credentials and refresh tokens reside in Cloudflare Worker secrets, not the public website or source files. D1 data is encrypted at rest and connections use TLS. EU database jurisdiction does not guarantee all Worker processing or third-party API processing remains inside the EU. Health and nutrition data is not sold, used for advertising or sent to an AI processor by these import modules. Google, Cloudflare and YAZIO process data as their respective providers.

5. User choice, retention and deletion

Only the owner authorizes Google Health access and chooses whether to connect the optional unofficial YAZIO integration. Google access may be revoked through Google Account connections. Disabling a schedule or disconnecting a provider prevents future imports but does not automatically erase previously imported data. Steps, sleep, HRV, weight, exercise and optional YAZIO daily totals have no automatic expiry; they are retained in the private D1 database until removed by the owner. The owner can delete nutrition history with DELETE FROM yazio_daily_nutrition; and delete the stored encrypted YAZIO token with DELETE FROM yazio_auth WHERE id=1; in the private Cloudflare D1 Console. YAZIO account sessions may also need revocation in YAZIO account settings. Cloudflare-managed backups may follow separate retention policies.

6. YAZIO API limitations

The YAZIO private API is not officially supported, published or endorsed by YAZIO. It may change, block access, or stop working at any time; using it is subject to YAZIO's terms. The project requires the owner's informed approval before connecting their account, and automatic synchronization remains off until they verify the imported nutrition figures. The module avoids repeated calls when access is blocked or rate limited.

7. Changes

This policy describes the existing private Google Health imports and optional experimental YAZIO nutrition integration. It will be updated before routine AI analysis, new data recipients/processors, or additional health categories are enabled.

8. Contact

For questions about the personal development project, contact the owner via the project owner's GitHub profile or the support email shown on the project's Google OAuth consent screen.

TRANSPARENCY & DATA PROTECTION

Privacy policy.

Personal Wellbeing is an independent personal-use wellbeing project in development. This policy explains the current testing purpose and data handling of its public information website.

Last updated: 19 October 2026

1. Purpose and status

Personal Wellbeing is an independent, single-owner personal wellbeing project. A separate Cloudflare Worker already synchronizes selected Google Health and optional YAZIO data. An optional private dashboard (version 0.7) is being prepared for deployment on the same Worker; it is not a public multi-user service. This GitHub Pages website is only a public information and privacy-policy site.

2. Google data and permissions

During testing, the owner may explicitly authorize read-only access to Google Health activity and fitness, sleep, and health metrics or measurements. These categories include workouts, steps, sleep sessions and stages, heart rate and weight. This project does not request permission to edit or delete Google Health data.

3. How data is used

The owner authorizes read-only access to selected Google Health data for private personal-development testing. A private Cloudflare Worker imports Fitbit/Google Health steps and, when enabled, overnight sleep, daily heart-rate variability (HRV), individual weight measurements and exercise summaries. The optional YAZIO module imports recent daily energy, protein, carbohydrate and fat totals via an unofficial YAZIO API. Provider measurements remain separate from manual corrections.

If the owner deploys the version 0.7 private wellbeing dashboard, the browser app will let them review those measurements and save morning/evening wellbeing check-ins (mood, energy and stress on 1–5 scales, optional tags and notes), custom habits with daily logs, and personal goals in their private Cloudflare D1 database. The app shows historical charts and non-medical, rule-based summaries. Data entered into these forms is sent over HTTPS to the owner's Worker, not to this GitHub Pages site. No external AI service receives health or habit data in version 0.7.

Notifications/reminders and external AI coaching are not active in this release. Missing provider measurements are not fabricated or treated as zero.

4. Storage, sharing and security

This public GitHub Pages information website has no sign-in, advertisements, user-entered health forms or behavioral analytics. GitHub may process standard infrastructure access logs.

The separate personal Cloudflare Worker stores configured provider health records, optional YAZIO nutrition totals, synchronization status and (when version 0.7 is deployed) private check-ins, habit entries, goals and pseudonymous login-rate-limit counters in the owner's D1 database configured for EU jurisdiction. Authentication uses an owner-controlled app password stored as a Cloudflare Worker secret and a separate signing secret. The app maintains a 12-hour signed session in an HttpOnly, Secure, SameSite=Strict cookie; the browser never needs the separate Cloudflare ADMIN_TOKEN. The password itself and the session cookie are not stored in D1. Login attempts are rate-limited using a pseudonymous HMAC-derived key rather than saving the raw IP address in the table.

OAuth tokens are stored as Cloudflare secrets; the optional YAZIO renewal token is encrypted with a separate Worker secret before storage in D1. Cloudflare encrypts D1 data at rest and data is transferred with TLS. EU D1 jurisdiction does not guarantee that all Worker or third-party API processing remains inside the EU. The app's service worker caches only static interface assets, not health data or authenticated API responses.

Health and nutrition records are not sold, used for advertising or sent to external AI providers in this release. Cloudflare, Google and optional YAZIO act as respective infrastructure/API service providers.

5. User choice, retention and deletion

Only the owner authorizes provider integrations and can revoke Google access via Google Account connections. Turning off a schedule or revoking provider access prevents new imports but does not automatically erase already imported records. Provider data, check-ins, habit logs and goals have no automatic expiration and remain until manually deleted by the owner. Habits and goals may be archived in the interface while preserving prior history. For complete deletion the owner can execute deletion queries against relevant private D1 tables or delete the entire database. The owner can clear YAZIO nutrition history and connection tokens from the relevant D1 tables and remove integration secrets from Cloudflare. Cloudflare infrastructure backups may follow their separate retention policies.

6. YAZIO API limitations

The YAZIO private API is not officially supported, published or endorsed by YAZIO. It may change, block access, or stop working at any time; using it is subject to YAZIO's terms. The project requires the owner's informed approval before connecting their account, and automatic synchronization remains off until they verify the imported nutrition figures. The module avoids repeated calls when access is blocked or rate limited.

7. Changes

This policy covers the private Google Health and optional unofficial YAZIO imports as well as the planned version 0.7 wellbeing dashboard. It will be updated before AI coaching, push notifications, additional health categories or new data processors are enabled.

8. Contact

For questions about the personal development project, contact the owner via the project owner's GitHub profile or the support email shown on the project's Google OAuth consent screen.

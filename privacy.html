TRANSPARENCY & DATA PROTECTION

Privacy policy.

Personal Wellbeing is an independent personal-use wellbeing project in development. This policy explains the current testing purpose and data handling of its public information website.

Last updated: 19 October 2026

1. Purpose and current status

The proposed app is intended to help its owner understand associations between habits and wellbeing. No functioning public habit-tracking product is deployed here. This website provides project information and its privacy policy only.

2. Google data and permissions

During testing, the owner may explicitly authorize read-only access to Google Health activity and fitness, sleep, and health metrics or measurements. These categories include workouts, steps, sleep sessions and stages, heart rate and weight. This project does not request permission to edit or delete Google Health data.

3. How data is used

The owner authorizes read-only access to selected Google Health records for private personal-development testing. A private Cloudflare Worker imports reconciled Fitbit/Google wearable step totals for the latest seven local days and, once enabled, primary overnight sleep summaries for the latest seven wake-up days. Sleep summaries include duration, timing and light/deep/REM stages when available; raw sleep-stage timelines are not stored.

If the owner activates the optional HRV module, the Worker additionally fetches seven days of reconciled daily wearable heart rate variability (HRV). Each daily summary is stored by Google's reported civil date, with average RMSSD in milliseconds and optional deep-sleep RMSSD, if supplied. It does not import ordinary heart rate or synthesize missing HRV values. Repeated imports update source measurements while preserving separately recorded manual overrides.

The Google API connectivity probe checks for accessible step records without storing the step value. The public GitHub Pages information website collects no health records. Workouts, weight, YAZIO nutrition, AI processing and a user-facing dashboard are not yet operational in this module.

4. Storage, sharing, and security

This public information website has no sign-in, behavioral analytics, advertisements or health-data upload forms. GitHub Pages hosts the static site and may process normal server access logs.

A separate private Cloudflare Worker stores synchronization timestamps and outcomes, daily wearable steps, sleep summaries when enabled, and daily HRV summaries if the optional HRV importer is activated, in a D1 database configured for EU jurisdiction. The HRV table includes the source civil date, RMSSD measurements where available, source family, fetched and created timestamps, and an optional manual override. Neither the public health-check nor synchronization-status endpoint returns these health measurements. OAuth credentials and refresh tokens are stored as Cloudflare Worker secrets, not in the public site, source files, or D1. D1 data is encrypted at rest and connections use TLS. EU database jurisdiction does not guarantee that all Worker or Google API processing remains within the EU.

Health measurements are not sold, used for advertising or sent to an external AI processor by this module. Google and Cloudflare are infrastructure/API providers for this processing.

5. User choice, retention and deletion

Only the owner authorizes Google Health read-only scopes and can revoke access through Google Account connections. Revocation stops new imports once authorization is invalid, but does not automatically erase stored D1 data. Steps, sleep summaries and, if enabled, daily HRV summaries have no automatic expiry and remain until the owner manually deletes them or removes the database. The owner can delete individual records or clear tables using the private Cloudflare D1 Console, disable scheduled synchronization, or remove Worker secrets. Cloudflare-managed backups may follow separate retention policies.

6. Other services

An integration with YAZIO for daily calorie intake is being investigated. YAZIO credentials and nutrition data are not collected by this website, and a YAZIO integration is not currently operational.

7. Changes

This policy describes the working step synchronization, sleep summaries and the optional daily HRV upgrade. It will be revised before additional health categories, YAZIO nutrition, routine AI analysis, or another data recipient or processor is enabled.

8. Contact

For questions about the personal development project, contact the owner via the project owner's GitHub profile or the support email shown on the project's Google OAuth consent screen.

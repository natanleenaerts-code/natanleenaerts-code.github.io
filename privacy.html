TRANSPARENCY & DATA PROTECTION

Privacy policy.

Personal Wellbeing is an independent personal-use wellbeing project in development. This policy explains the current testing purpose and data handling of its public information website.

Last updated: 19 October 2026

1. Purpose and current status

The proposed app is intended to help its owner understand associations between habits and wellbeing. No functioning public habit-tracking product is deployed here. This website provides project information and its privacy policy only.

2. Google data and permissions

During testing, the owner may explicitly authorize read-only access to Google Health activity and fitness, sleep, and health metrics or measurements. These categories include workouts, steps, sleep sessions and stages, heart rate and weight. This project does not request permission to edit or delete Google Health data.

3. How data is used

The owner manually tests Google Health API connectivity through Google's OAuth Playground and a private Cloudflare Worker. The connectivity probe reads at most one step record without storing its value. If the owner deploys the optional daily-steps sync upgrade, the private Worker also fetches reconciled Fitbit/Google wearable step totals for the current civil day and previous six days, upserting each available daily total into a private Cloudflare D1 database. Historical totals are retained until the owner deletes them; repeated sync runs can revise the source total but do not erase separately stored manual overrides.

This is a personal development project, not a public wellbeing app. The public GitHub Pages website does not collect, process or store health records. Sleep, exercise, heart rate, weight, YAZIO nutrition, AI analysis and a personal dashboard are not imported or enabled by this daily-steps module. The owner will update this policy before enabling additional types or processors.

4. Storage, sharing, and security

This public information website has no sign-in, behavioral analytics, advertisements or health-data upload forms. It is hosted on GitHub Pages; GitHub may process ordinary access logs for operation and security. Google OAuth Playground requests are subject to Google's policies.

The separate, private Cloudflare Worker stores synchronization timestamps and non-sensitive success/error statuses in a D1 database constrained to the EU jurisdiction. When the optional daily-steps importer is deployed, that D1 database also stores daily step totals and the import timestamp. D1 encrypts data at rest, and connections use TLS. The EU D1 storage constraint does not imply that all Worker processing or Google API processing occurs exclusively within the EU. OAuth client credentials and refresh tokens are stored as Cloudflare Worker secrets, rather than website content, source files or D1 records. The Worker does not return step totals from its public healthcheck or synchronization status endpoints.

Information is not sold, used for advertising or intentionally shared with external AI services. Google and Cloudflare process data as infrastructure/API service providers.

5. User choice, retention and deletion

The owner determines which Google Health read-only scopes to authorize. Access can be revoked via Google Account connections. Revoking consent stops new Google imports when tokens become invalid, but does not automatically erase previously imported D1 totals. The owner controls this private Cloudflare database and can remove historical totals by securely running a database deletion query, and can disable scheduled runs or remove Worker secrets. No automatic expiry is currently configured for imported step totals; they remain until the owner deletes them or removes the database. Cloudflare infrastructure may maintain backups subject to its service policies.

6. Other services

An integration with YAZIO for daily calorie intake is being investigated. YAZIO credentials and nutrition data are not collected by this website, and a YAZIO integration is not currently operational.

7. Changes

This policy describes the optional first daily-steps sync capability. It will be updated before deploying additional health categories, YAZIO nutrition, user-facing sign-in, routine AI analysis or data sharing with other processors.

8. Contact

For questions about the personal development project, contact the owner via the project owner's GitHub profile or the support email shown on the project's Google OAuth consent screen.

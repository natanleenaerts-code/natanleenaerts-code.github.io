TRANSPARENCY & DATA PROTECTION

Privacy policy.

Personal Wellbeing is an independent personal-use wellbeing project in development. This policy explains the current testing purpose and data handling of its public information website.

Last updated: 19 October 2026

1. Purpose and current status

The proposed app is intended to help its owner understand associations between habits and wellbeing. No functioning public habit-tracking product is deployed here. This website provides project information and its privacy policy only.

2. Google data and permissions

During testing, the owner may explicitly authorize read-only access to Google Health activity and fitness, sleep, and health metrics or measurements. These categories include workouts, steps, sleep sessions and stages, heart rate and weight. This project does not request permission to edit or delete Google Health data.

3. How data is used

The owner tests read-only Google Health connectivity using Google OAuth Playground and a separate private Cloudflare Worker. The Cloudflare probe, when enabled by the owner, obtains a temporary access token, reads at most one Google Health step record to check connectivity, and responds with a success status only. It does not store or return the measured step value. The static public website does not collect, upload, analyze or store health records.

This is a personal development test, not a functioning wellbeing app. Before continuous import or storage of health measurements or AI processing, this policy will be revised to identify data types, processing purposes, infrastructure, retention, user controls and deletion options.

4. Storage, sharing, and security

This public information website has no sign-in, behavioral analytics, advertisements or health-data upload forms. It is hosted by GitHub Pages; GitHub may process ordinary access logs for operation and security. Google OAuth Playground requests are subject to Google's terms and privacy practices.

Separately, a private Cloudflare Worker records infrastructure-only synchronization timestamps and success/error status in an EU D1 database. It currently does not persist personal health measurements. When a Google cloud connectivity probe is configured, OAuth client credentials and a renewable token are held as Cloudflare Worker secrets, not in the public website or its repository. The temporary access token and the fetched test record are not persisted by the probe. Cloudflare acts as the cloud infrastructure provider for this private test.

The project does not sell health data, use it for targeted advertising or transfer it to advertising services.

5. User choice and revocation

Only the owner chooses whether to grant Google Health permissions. Google account authorization can be revoked at Google Account connections. Since the static site stores no Google Health measurements, there is no such record on this website to download or delete.

6. Other services

An integration with YAZIO for daily calorie intake is being investigated. YAZIO credentials and nutrition data are not collected by this website, and a YAZIO integration is not currently operational.

7. Changes

We will revise this policy before introducing any operational cloud data storage, ongoing synchronization, AI analysis or additional external service connections.

8. Contact

For questions about the personal development project, contact the owner via the project owner's GitHub profile or the support email shown on the project's Google OAuth consent screen.
